# LastGood

### It worked yesterday. You pulled. Now it doesn't. LastGood tells you what changed.

**LastGood remembers the last state your project actually worked in — and after a `git pull` or a branch switch, tells you exactly what drifted since then** (dependencies, migrations, env vars, runtime, services) with the commands to get running again.

It runs on your machine. Nothing is uploaded. No account.

## Why

Everyone knows the feeling: the project ran fine on Friday, you `git pull` on Monday, and now it's broken. The fix is usually small — reinstall, run one migration, add an env var — but finding *which* one eats half an hour of you and your AI assistant guessing.

LastGood removes the guessing. When the project works, you save a snapshot (`lastgood mark`, or automatically when your tests pass). Later, `lastgood morning` compares now against that snapshot and tells you precisely what changed, ranked, each with a fix.

It follows one rule: **detect facts, never guess.** It won't say "the migration broke it." It says *"1 migration was added since your last-good state and may not be applied locally,"* and hands you `npx prisma migrate dev`. You — or your AI — draw the conclusion.

## The 20-second demo

```bash
# 1. Project works — save the good state (or let `lastgood run -- npm test` do it on success)
lastgood mark

# 2. ... git pull ... a teammate bumped deps, added a migration, added an env var ...

# 3. Find out what changed
lastgood morning
```

## What it captures

When you `mark`, LastGood saves a small, **local-only** fingerprint (in `.lastgood/`, gitignored):

- Git commit + branch + uncommitted-file count
- Lockfile hashes (npm/pnpm/yarn/bun, pip/poetry/uv, Cargo, Go, Gradle, Composer, Bundler)
- Installed runtime versions (Node/Python/Java/.NET/Go/Ruby)
- The **names** of env vars your project documents (`.env.example`) — **never the values**
- Docker-compose services and declared ports
- Migration file counts (Prisma/Drizzle) — on disk, the DB is never touched
- Hashes of schema / generated files and any paths you add to `watch_paths`
- The command that defined "working" and how it exited

`lastgood diff` (alias `morning`) compares the last-good fingerprint to now and reports the differences.

## For your AI agent

```bash
lastgood context
```

writes `.lastgood/verified-context.md` — a strictly factual snapshot an AI coding agent (Claude Code, Cursor, Copilot, Codex) can read instead of hallucinating:

```markdown
# Verified Project Context — generated by LastGood (facts only, no inference)

## What changed since the project last worked
BLOCKING:
- package-lock.json changed since your last-good state.  Fix: `npm install`
- 1 prisma migration was added since last-good and may not be applied locally.

## Ground truth
- "Working" is defined as: `npm test` exits 0.
- This file contains only detected facts. It draws no conclusions about causes.
```

Instead of giving your agent *more* context, you give it **verified** context.

## Commands

```
lastgood init             scaffold lastgood.yml and .lastgood/
lastgood mark             save the current state as last-good (--note "...")
lastgood run -- <cmd>     run your success command; if it exits 0, auto-mark
lastgood diff             what changed since last-good  (alias: morning)
lastgood context          write .lastgood/verified-context.md for an AI agent
lastgood park             end-of-day capsule + a note to your future self (--note)
lastgood resume           replay your park capsule and show what changed since
lastgood langs            list UI languages

  --json          machine-readable output (diff)
  --report [f]    also write a markdown report (diff)
  --lang <code>   UI language (20 supported, incl. RTL)
```

`lastgood diff` exits `2` when something blocking changed, `0` when clean — so it works as an onboarding gate too.

## Full control — `lastgood.yml`

`lastgood init` writes this; everything is opt-in/opt-out. No network, no telemetry, no secret storage — by default *and* by design.

```yaml
version: 1
success_command: "npm test"     # exit 0 => auto-mark
run_on_success: true

privacy:
  store_env_values: false   # HARD DEFAULT — values are never read, regardless
  cloud_sync: false         # local-only; no network calls, ever

detectors:
  git: { enabled: true }
  lockfiles: { enabled: true }
  runtimes: { enabled: true }
  env_schema: { enabled: true }
  docker: { enabled: true }
  ports: { enabled: true }
  migrations: { enabled: true, tools: [prisma, drizzle] }
  schema: { enabled: true, hash: ["prisma/schema.prisma", "src/db/schema.ts"] }

watch_paths: []
ignore: ["**/*.log", "tmp/**"]
diff: { fail_on: blocking }
```

`store_env_values: false` isn't just a default — LastGood has no code path that reads a `.env` value. It reads key names only.

## FAQ

**Why did my project stop working after `git pull`?**
Run `lastgood morning`. It compares now against the last state you marked as working and lists exactly what changed — deps, migrations, env vars, runtime, services — with a fix for each.

**Which migrations do I need to run after switching branches?**
LastGood counts migration files on disk and tells you how many were added since last-good (it never touches your database), with the apply command.

**How do I find which new environment variable I'm missing after a pull?**
It diffs `.env.example` **key names** across time and flags the newly-expected keys — without ever reading a value.

**How do I give my AI coding agent accurate context about my project?**
`lastgood context` writes a facts-only `verified-context.md` your agent can read — versions, changed deps, unapplied migrations, missing env keys — with an explicit "draws no conclusions" line so it reasons from evidence.

**Is it really local?**
Yes. It reads project files and runs read-only commands already on your machine. No network calls, no telemetry, nothing uploaded. The fingerprint lives in `.lastgood/` and is gitignored. MIT licensed.

## How it compares

No tool combines the four things LastGood does: **(a)** a saved last-known-good local state, **(b)** a diff since then, **(c)** the exact prep-to-run after a pull, and **(d)** verified factual AI context. `git-pull-run` auto-runs a command after pull but is blind to *what* changed; `.env` diff tools only cover env; Nix/devcontainers *prevent* drift by pinning everything (a big commitment) rather than explaining an un-pinned repo. LastGood is the small thing you drop into any repo to answer "what changed since it worked?"

## Roadmap

- Git hooks (`post-merge` / `post-checkout`) that nudge you to run `morning`
- More migration tools (Alembic/Flyway/Rails/Django, read-only status)
- CI status of the branch via the GitHub CLI
- Plugin detectors and a VS Code status-bar indicator

LastGood is one of a small suite of local-first developer tools. **PatchProof** answers *"is this code change correct?"* before you commit; **RepoDoctor** answers *"is my environment healthy right now?"* — all sharing one principle: **detect facts, don't guess.**
